   115→   415→### 2.6 Schema Issues Found
   116→   416→
   117→   417→**S-1: No Prisma Enum Definitions — All Status Fields Use Plain String [MEDIUM]**
   118→   418→- **Files:** prisma/schema.prisma (throughout, 35+ fields)
   119→   419→- **Detail:** Status fields like `status String @default("ACTIVE")` use plain strings instead of Prisma enums. Values like ACTIVE/INACTIVE/SUSPENDED, NEW/QUALIFIED/WON/LOST, etc. are defined only in code comments.
   120→   420→- **Impact:** No database-level constraint on valid values. Any arbitrary string can be inserted. Loss of type safety in Prisma client.
   121→   421→- **Recommendation:** Define `enum TenantStatus { ACTIVE SUSPENDED TRIAL }`, `enum LeadStatus { NEW QUALIFIED ... }`, etc. in the schema.
   122→   422→
   123→   423→**S-2: Employee → User Cascade Delete May Delete User Account [HIGH]**
   124→   424→- **File:** prisma/schema.prisma:913
   125→   425→- **Detail:** `user User @relation("EmployeeProfile", fields: [userId], references: [id], onDelete: Cascade)` — Deleting an Employee record will cascade-delete the associated User account, which would also cascade-delete all their Memberships, RefreshTokens, and other user data.
   126→   426→- **Impact:** Accidental employee deletion would lock the user out of the system entirely.
   127→   427→- **Recommendation:** Change to `onDelete: Restrict` to prevent deleting an employee if they have a linked user account, or `onDelete: SetNull` (but this requires making userId nullable).
   128→   428→
   129→   429→**S-3: StageHistory Missing tenantId [LOW]**
   130→   430→- **File:** prisma/schema.prisma:603-617
   131→   431→- **Detail:** StageHistory has no tenantId field. It's only reachable via Deal (which is tenant-scoped), but direct queries would lack tenant filtering.
   132→   432→- **Impact:** Minimal — StageHistory is always queried through a parent Deal. But if code ever queries StageHistory directly without joining through Deal, it could return cross-tenant data.
   133→   433→- **Recommendation:** Add `tenantId String @map("tenant_id") @db.Uuid` and a corresponding `@@index([tenantId])`.
